# 算法、数值约定与验证

MoonStretch 独立实现波形相似重叠相加（WSOLA）、带限速率转换及能量周期 BPM 估计。它没有调用 SoundTouch、Rubber Band 或浏览器的变速算法，也不要求复现这些实现的逐采样输出。与成熟工具的功能关系见 [生态与范围说明](ECOSYSTEM.md)。

## 两级音频变换

令用户设置的半音数为 `s`，`p = 2^(s/12)`。内部先以 `a = tempo / p` 做 WSOLA 时间伸缩，再以 `b = p * rate` 做播放速率转换：

```text
交织 PCM -> WSOLA(a) -> 带限速率转换(b) -> 交织 PCM
```

固定参数时，两级时长倍率相乘为 `1/(tempo*rate)`，频率目标倍率为 `p*rate`，因而 Pitch 不改变最终时长。两级内部比率均在 0.25–4，覆盖公开参数的全部组合。动态变化时这两个比例在连续时钟上生效；不能把最后的 a、b 套到之前已处理的音频。

## WSOLA 的窗口与时间对齐

所有声道共同参与归一化相关计算并共享偏移。实现没有先把立体声相加成单声道，反相信号仍有有效对齐信息。每次合成一个 hop，并保留同样长度的重叠尾部：

| 根 API 档位 | hop / 尾部长度 | 理论位置两侧的搜索半径 | 粗搜索预算 |
| --- | --- | --- | --- |
| Speech | 10 ms | 5 ms | 约 128 个重叠采样位置、96 个候选偏移 |
| Balanced | 20 ms | 10 ms | 同上，为原默认参数 |
| Music | 40 ms | 15 ms | 约 256 个采样位置、192 个候选偏移 |

毫秒按采样率换算为整数帧。内部 `stretch.new` 允许 hop_ms 为 1–80、search_ms 为 0–40；根 API 提供上述经过验证的三档。搜索先用稀疏相关选择候选区，再在附近逐帧计算完整重叠相关。Music 增加粗搜索密度，并非在最高采样率下对全部偏移进行穷举。这些配置是前瞻、计算量和信号特性的取舍，不代表 Music 对每种信号都更好。

相同分数优先选择靠近理论时钟的位置。固定控制的理论位置为 `round(emitted_frames*a)`，不沿上次相关搜索胜出的偏移继续累积，因此不会因持续选择搜索区同一侧而长期漂移。

动态模式保存 `analysis_frame + analysis_fraction`。每合成 h 帧，将这个源时钟推进 `h*a`，其中整数和小数分别保存。`set_tempo` 改变后续推进量，不更改当前时钟，也不丢弃已保留的重叠尾部。跨越 a=1 时继续使用该状态，不能切入会丢历史的固定恒等捷径。

相关计算按共享峰值缩放，公共输入还限制绝对值不超过 `1e100`，避免有限大数参与平方运算时溢出。重叠采用互补线性权重。只保留未来窗口可能访问的输入与尾部；终止时对有限录音使用零延拓。固定 a=1 路径直接复制样本，动态 a=1 则维持窗口和前瞻。

## 带限速率转换与动态历史

滤波核为归一化 Blackman 窗 sinc，使用 512 个小数相位区间及相邻表插值。滤波半径为 `ceil(48*max(1,b))`，截止系数为 `0.9/max(1,b)`。下采样时扩大输入窗口、降低截止频率，抑制超出新奈奎斯特频率的成分；这是有过渡带的有限 FIR，不是理想砖墙滤波器。

源位置用 Int64 整数帧与一个小的小数相位保存。每输出一帧推进 b，避免把长录音的时间戳一直累加到单个大浮点数。边界使用端点延拓；固定 b=1 精确立即直通。

动态模式保留最大支持半径 192 帧的过去历史。改变 b 时更新滤波系数，但不重置小数相位、源位置或 PCM；相同值不重建系数。未来窗口仍按当前滤波半径等待足够输入。动态 b=1 且相位为整数时精确取原样本，同时保留历史和前瞻以便后续变速；小数相位仍需插值。

动态参数更新不会修改已经输出的 PCM，但可能作用于仍在前瞻区的输入。滤波器切换、WSOLA 窗口或速率的突然变化可能产生过渡瞬态；当前没有无点击参数 ramp，也没有输入帧精确事件调度。

## 固定长度与动态结束的不同约定

固定两级处理分别取整可能产生少量末尾差异。根 Stream 保留至多八帧的常规输出余量，完成后统一到 `floor(N/(tempo*rate)+0.5)`。需要补足时仅重复最后一帧修正不超过八帧的取整差值，不能用它填补缺失窗口。事件时间与频率有独立测试，不仅检查长度。

动态流不以最终参数计算整条流的目标长度。设 WSOLA 当前源时钟为 x、已接受 N 帧，它在 finish 时以当前 a 生成 `max(0,round((N-x)/a))` 个剩余输出帧；速率转换同样从其当前源相位到已接受末尾，按当前 b 计算余量。两级处理均延续已有状态，最后排空；没有逐块 flush 后重新拼接的路径。

动态流即便没有改变参数，也不承诺与固定模式逐样本、最终帧数完全相同：动态组合不做固定模式的统一末尾修正。需要精确固定时长应使用 Stream::new、process 或 Processor::new(adjustable=false)。

控制更新的时机是算法处理边界；改变 host 预取策略可能改变更新时尚未处理的前瞻。只在控制配置固定的输入区间内，按相同控制调用边界细分输入，才适合比较分块一致性；不能把按输出播放时间触发的更新与按输入帧触发的更新混为同一时间线。

## 前瞻、队列与内存

WSOLA 的前瞻预算为 `max(search+2*hop, ceil(hop*a))`，覆盖搜索窗口和较快分析时钟；固定 a=1 为零。重采样预算为当前滤波半径，固定 b=1 为零。组合预算为：

```text
stretch.latency_frames() + 4*resampler.latency_frames() + 32
```

系数 4 覆盖内部 WSOLA 最大源推进比例，额外余量覆盖组合输出保留及取整。这是算法前瞻的保守值，不是 CPU 耗时或最终设备延迟；当前控制变化后预算会改变。

push 接受完整帧并返回已生成 PCM，finish 只能排空一次，reset 保留当前配置并清空状态。根 Stream 分短块推进，DSP 的历史缓冲不会随录音长度线性增加。FIFO Processor 在其外层保留尚未消费的输出，调用方若不读取，队列会持续增长；应按 num_samples 实施背压和限量预取。

buffered_frames 统计保留的 PCM 帧，不能作为进程总内存：不包含调用方数组、返回数组、运行时开销或固定系数表。高比率下系数表最多约 20 万个 Double；动态改 rate 可能重新计算并分配该表。read_into 可复用宿主目标数组，但队列整理和 DSP 仍可能分配内存。CLI 默认与标准流模式读取整个文件；0.3.0 的 `--stream` 文件模式按块复用 MoonBit 编解码器、使用固定参数 FIFO 并及时排出，限制 PCM 保留量。它要求可定位文件，不支持自动 BPM 检测或标准流。这些接口均没有硬实时线程零分配或固定最坏执行时限保证。

## BPM 的独立分析

BPM 包对每个声道分别累计能量，再形成 200 Hz RMS 包络；反相声道不先相加，避免抵消。用整数时钟划分窗口，使 44.1 kHz 等采样率和输入分块不改变能量观察位置。只保留可配置的最近 8–60 秒包络，默认 20 秒，不保留原始 PCM。

检测使用平滑后的正向能量变化、中心化归一自相关、局部周期峰选择和插值。默认范围 60–200 BPM，可在 30–300 内设置；至少需要四秒以及最慢候选的三个周期。静音、稳态低动态信号、缺乏明显周期或数据不足返回 None。confidence 是选中周期的相关强度，不是正确概率。

它估计能量起音的重复速度，不识别拍号，不提供逐拍位置标注，也无法消除强弱拍造成的半拍/倍拍歧义。目标 BPM 转换允许明确传入已知 source BPM，并检查 `target/(source*rate)` 是否落入公开 tempo 范围。详情与限制见 [BPM README](../bpm/README.md)。

## 验证方法

MoonBit 测试覆盖公开参数、三档窗口、空/短输入、完整帧布局、结束/重置、错误原子性、固定控制分块不变性、FIFO 范围及计数。动态阶段测试还验证：

- 连续跨越比率 1，多次改变参数仍保留源时钟和分数相位；
- 局部正弦频率与按分段速率积分的独立解析相位相符；
- 反相立体声及八声道关系不会因独立对齐发生漂移；
- 最大滤波窗口扩张仍可读取过去历史，结束后释放保留 PCM；
- 各档前瞻预算覆盖窗口搜索和首次输出需求。

独立 Python 脚本不导入 MoonBit 算法，验证固定参数精确帧数、频率相对误差阈值 1.5%、反相及不同频率声道、恒等样本、分块、保留 PCM、已知事件时间和抗混叠 RMS。宿主验证另外覆盖动态播放、BPM 和 CLI，执行命令见 README。BPM 测试含多采样率合成打击音、错误状态、静音、稳态信号及滚动窗口边界。

SoundTouch 对照作为独立进程处理测试音，比较时长、频率和可比控制语义，不要求不同算法波形一致。CI 保存实际结果，未执行的后端或设备不能当作已验证。

解析信号、合成事件和数值回归不等同于真实语音/音乐主观听评。密集复音、打击乐和极端拉伸可能产生抖动、拖尾或瞬态变形；本项目没有共振峰保持或自动修音。未有对应数据时，不宣称优于成熟引擎或适用于所有音乐制作任务。
