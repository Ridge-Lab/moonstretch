# 验证证据与判断边界

评审和开发使用同一套可运行检查。入口是 `python scripts/verify.py`，各测试仍可单独运行；不要求安装额外测试框架。完整流程和失败处理见根目录 `CONTRIBUTING.md`。

## 四项标准对应到实际成果

| 维度 | 实现与可复现证据 | 不能由此推出的结论 |
| --- | --- | --- |
| 工程深度 | 同一 DSP 状态持续调参，播放器 FIFO、结束/重置、浏览器按需生产，以及 `--stream` 文件管线。`verify_stream_cli.mjs` 比对五种 PCM 编码、不同分块、短尾、八声道、无覆盖及失败清理。 | 浏览器已经具备麦克风或流式文件解码；所有格式完整兼容。 |
| 技术贡献 | WSOLA 多声道共同对齐、重采样相位/滤波历史保留、分块无关的状态和固定/动态时间线。种子测试在相同输入事件边界下改变生产和消费节奏，逐样本核对结果及错误后的状态。 | 使用公开算法本身就是新算法；合成信号正确意味着复杂音乐听感优秀。 |
| 生态增量 | 承认 MoonMel 已有离线效果和 BPM；提供可播放 PCM 的持续控制、消费者取数和真实文件接入。SoundTouch 以同组输入/参数分别对解析期望测量；长文件检查首批输出与保留 PCM。 | 这些项目已采用本库，或测量证明比成熟库音质/性能更好。 |
| 开发与验证 | CI 与本地共用入口；源码指纹、工具链、命令、失败日志和数值报告随运行保存。检查器有失败传播回归，音频判据有故障注入与负对照。 | 所有错误均可检出；任务数等于测试数；注入测试等于生产代码变异覆盖率。 |

## 已发现问题如何成为回归

| 实际问题 | 历史证据或复现 | 防止复发 |
| --- | --- | --- |
| 有限但过大的 PCM 可能引发数值溢出，超长时间线耗尽计数 | 提交 `1281f229` 加入幅度/时间线边界及消费前拒绝 | `stream_wbtest.mbt`；种子状态测试还把非法值放在较长合法输入的尾部，核对拒绝后状态不变。 |
| PCM24 奇数数据长度漏算 RIFF padding；旧编解码器将 NaN/Inf 静默变为零 | 提交 `736fd669` 的容器兼容及浮点输入修复 | `wav/wav_test.mbt` 与 `verify_wav.mjs` 独立构造容器，检查长度和拒绝行为。 |
| 新文件管线用 Node ASCII 解码 FOURCC，高位异常字节可伪装成 RIFF/WAVE/fmt/data | 独立复核用 `0xD2` 替代 `R`，默认接口拒绝而新增路径接受；新增拒绝用例先失败，再改为保留字节的比较 | `verify_stream_cli.mjs` 四类高位标识回归，同时要求失败后无输出残留。 |
| 已分发网页遗漏 core NOTICE，第三方说明的 LICENSE 链接失效 | 0.2.1 补齐依赖原件与网页链接 | `build_web.mjs` 要求三份依赖声明存在且与源文件完全一致，构建失败不能继续部署。 |

上述问题与人为故障注入分开记录。`verify_faults.py` 只测试判据对选定错误是否敏感：真实引擎基线先通过，再注入错误参数、交换声道、丢帧/重复、非法样本、错误格式等。驱动崩溃不算成功检出；`1e-12` 微扰应被接受，防止检查器把所有变化都视为错误。

## 数据与复现

`full` 生成 PCM、持续控制、文件管线、BPM、故障敏感性及块处理耗时报告。每次运行目录唯一；主报告记录所有子报告哈希和源码状态，旧文件不能抵充本次结果。运行过程中修改源码会使该次验证失败。CI 在 Linux 强制要求 SoundTouch 对照，在 Windows 明确记录该项未执行。

分块文件场景默认使用 4,096 帧。4 秒与 60 秒双声道 8 kHz 测试分别处理 32,000 与 480,000 输入帧，检查首次输出早于文件结束、读取块不随录音长度增长，以及保留 PCM 没有按时长增长。原始数值以本次运行的 `stream-cli-quality.json` 为准；这不是对系统缓存、垃圾收集或进程峰值内存的完整测量。

性能报告按硬件与后端解释，不设跨设备硬实时承诺。测试素材为程序合成；实际语音、密集复音、打击乐的授权试听及真实使用反馈仍是后续质量证据，不能用自动测试代替，也不捏造第三方采用。
